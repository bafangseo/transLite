# 1.1.1 发布说明

修复用户反馈最集中的问题：重启电脑或关闭浏览器后被要求重新输入 API Key。并修复长文章页面上的"模型返回的译文数量或格式不匹配"报错。

## 变更

### API Key 默认持久保存

- 1.1.0 把密钥只放在 `chrome.storage.session`，浏览器一退出就清空；"加密记住"模式也要求每次启动后手输解锁密码。两条路径对用户而言都等于"每次重启重新输入"。
- 1.1.1 起，不勾选加密选项时密钥保存在 `chrome.storage.local`（已设为 `TRUSTED_CONTEXTS`，网页内容脚本不可读；不通过 Chrome 同步）。重启浏览器后直接可用。
- "用密码加密保存"保留为可选的高安全模式：勾选后不再保留明文副本，只保存 AES‑GCM 密文，解锁后的密钥仅在本次会话内存中。
- 在已保存明文密钥的情况下勾选加密并设置密码，无需重新输入密钥即可升级为加密保存；"清除密钥"同时删除明文、密文与会话副本。
- 从 1.1.0 升级的用户：旧密钥本来就不在持久存储中，升级后需再输入一次，之后不再提示。

### 长文章分段修复

- 文章外层容器使用 `overflow: hidden/clip` 做布局时（如 Hugging Face 博客），1.1.0 会把正文误判为"紧凑控件"，拆成逐链接、逐加粗的碎片发给模型，极易触发数量不匹配错误。现在只有矮盒子（高度小于 160px 或设有 `max-height`）的裁剪才视为截断风险。
- 模型输出解析更宽容：容忍 code fence、残留 `<think>`、夹带解释文字、对象包装和数字项；批量返回数量不符时自动逐条重试并保持顺序。

## 验证

`npm test` 全部通过。新增覆盖：

- 单元：明文密钥保存在 local 且不进 sync / 消息；会话清空后 `hasKey` 仍为真；明文→加密升级、失败升级不丢失密钥、清除删除所有副本。
- 浏览器：安装后的 MV3 扩展保存密钥 → 完全关闭并重新启动 Chromium → 设置页无解锁提示、`GET_SETTINGS.hasKey === true`、连接测试成功。
- 浏览器：高 `overflow:clip` 容器内的段落保持整句双语对照。

## 发布前手工验收

1. 从 1.1.0 升级安装：确认提示重新输入一次密钥，保存后重启电脑，打开任意网页按 Alt+T 可直接翻译。
2. 勾选"用密码加密保存"保存后，检查 `chrome://extensions` → 扩展详情 → 检查视图中 `chrome.storage.local.get()` 不含明文密钥；重启后需解锁。
3. 商店后台"隐私权规范"中数据处理说明与新的 `privacy.html` 保持一致（API Key 本机存储，不同步）。
4. 1.1.0 的验收项（原生授权弹窗、真实 Qwen 账号测试连接、始终翻译站点权限范围）仍然适用，见 [release-1.1.0.md](release-1.1.0.md)。
