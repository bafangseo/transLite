# 1.2.0 发布说明

新增一条免配置、免密钥的微软翻译通道，并为它配了批量请求：同样一页内容，请求数约为 Google 通道的四分之一。

## 变更

### 新增微软翻译（免密钥）

- 接入点是 `https://edge.microsoft.com/translate/translatetext`，即 Microsoft Edge 浏览器内置翻译所用的接口。不需要 API Key、不需要登录，不读写任何 cookie（请求显式 `credentials: omit`），也不伪装 User-Agent 或 Referer。
- 协议很朴素：请求体是一个**纯字符串数组** `["Hello world", "Good morning"]`，响应是等长的 `[{ translations: [{ text, to }] }]`，顺序严格对应。因此不需要 Google 通道那套 `⟦LT⟧` 分隔符，也就不存在"分隔符被翻译掉导致整批重发"的失败模式。
- 语种码按 Edge 的命名折算：`zh-CN → zh-Hans`、`zh-TW → zh-Hant`、`pt → pt-PT`，其余与扩展内部语言码一致。
- 不传源语言，由服务端自动检测（响应会带 `detectedLanguage`），省掉一次本地语言判断。
- 分批策略：单段按 1800 字切分，单批最多 50 段 / 8000 字。实测 30 段短文一次请求完成、5399 字长文切 3 段后仍是一次请求；Google 通道同等内容约需 4 次。
- 结果校验从严：返回条数与请求条数不等、或任一条译文为空，整批直接报错交给"重试未完成内容"，不会把半截译文写进页面。
- 隐私与授权口径不变：请求由后台 Service Worker 发出，接收方在弹窗和设置页照常显示，首次使用仍需勾选同意并授权访问该服务；失败时只提示重试，**不会静默改走另一个翻译服务**。

### 通道之间互不影响

- 微软单独占用凭据槽 `credentialMicrosoft` / `vaultMicrosoft`。此前"AI 接口 ↔ 新服务"来回切换会因接口地址变化触发清理，把已保存的 API Key 一并删掉；这条路径已补回归测试。
- 免密钥服务统一由 `LT_CONFIG.needsKey()` 判定。选择 Google 或微软时，设置页不再显示 API Key 区块，弹窗也不再提示"请先填写密钥"。

### 其它

- 新增服务说明与更新日志。
- 隐私说明补充微软接收方与 Microsoft 隐私声明链接，两份副本（根目录与 `src/`）保持一致。

## 验证

`npm run test:unit` 全部通过（43 项，新增 3 项）：

- 单元：微软通道无需密钥、`SAVE_SETTINGS` 后 `hasKey === false`；请求为 `POST`、URL 含 `translate/translatetext` 且 `to=zh-Hans`、`isEnterpriseClient=false`、**不含 `from`**；请求体是裸字符串数组。
- 单元：返回条数与请求不符时整批失败，错误信息为「数量不匹配」。
- 单元：`AI 接口 → 微软 → AI 接口` 往返后，已保存的 API Key 仍在。
- 真实端点冒烟（非自动化测试）：`["Hello world","Good morning. How are you today?"]` → 「你好，世界」「早上好。你今天怎么样？」；`to=zh-Hant` → 「哈囉，世界」；30 段批量与 5399 字长文均各 1 次请求完成。

## 发布前手工验收

1. 全新安装（无任何已存设置），直接选「微软翻译」，不填任何密钥即可保存。
2. 打开一个英文网页点「翻译此页面」：首次会请求 `https://edge.microsoft.com/*` 与当前站点权限，同意后正常出双语对照。
3. 在设置页把服务在「AI 模型翻译 → 微软翻译 → AI 模型翻译」之间来回切换并各保存一次，确认此前填过的 API Key 没有被清掉。
4. 找一个长页面（如一篇文章）对比请求数：微软通道应只发出个位数请求，翻译结果与原文段落一一对应、不漏段、不串段。
5. Steam 内置浏览器（全站授权版）：在创意工坊页面选微软翻译，确认悬浮按钮进设置后能选中该服务并正常翻译。
6. 商店后台「隐私权规范」中的数据处理说明与 `privacy.html` 保持一致（新增 `edge.microsoft.com` 接收方）。
7. 1.1.1 的验收项（密钥持久化、加密保存、长文章分段）仍然适用，见 [release-1.1.1.md](release-1.1.1.md)。
